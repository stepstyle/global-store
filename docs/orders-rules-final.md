# إغلاق إنشاء وقراءة الطلبات من المتصفح — خطة الانتقال

> **الحالة:** جاهز ومختبر محليًا فقط. لم يُنشر شيء. النشر يحتاج موافقة صريحة منفصلة.

## الثغرة في القواعد المنشورة (`firebase/firestore.rules.on-delivery`)

أثبتها `firebase/rules-test/orders-final.test.mjs` على المحاكي:

| الحالة | القواعد الحالية | القواعد النهائية |
|---|---|---|
| زائر ينشئ طلبًا مباشرة (بلا Turnstile ولا فحص أسعار ولا Telegram) | **مسموح** | ممنوع |
| مستخدم ينشئ طلبًا يظهر في «طلباتي» لزبون آخر | **مسموح** | ممنوع |
| الأدمن ينشئ طلبًا من المتصفح | **مسموح** | ممنوع (الطلبات من الـ Worker فقط) |
| أي شخص يملك رقم الطلب يقرأ الاسم والهاتف والعنوان | **مسموح** | ممنوع |
| مستخدم آخر يقرأ طلب زبون برقمه | **مسموح** | ممنوع |
| الزبون يقرأ طلبه ويعرض «طلباتي» | مسموح | مسموح |
| الأدمن يقرأ ويعرض كل الطلبات | مسموح | مسموح |
| الأدمن يغيّر حالة طلب قديم (v1) | مسموح | مسموح |
| تغيير حالة طلب Worker مباشرة (تجاوز المخزون) | ممنوع | ممنوع |
| حذف طلب Worker ما زال محجوزًا | ممنوع | ممنوع |

**الفرق الوحيد عن القواعد المنشورة:** قسم `orders` فقط، أي `create: false` و`get/list` للأدمن أو صاحب الطلب. باقي الملف مطابق حرفيًا.

## الاختبارات

| الاختبار | النتيجة |
|---|---|
| جدول القواعد (القواعد الحالية مقابل النهائية) | 36/36 |
| سيناريوهات الطلب والمخزون والتسليم تحت القواعد النهائية | 13/13 (`E2E_RULES=on-delivery-final E2E_SUITE=delivery`) |
| سيناريوهات الدفع في المتصفح تحت القواعد النهائية (ضيف، مسجل، تبويبان، انقطاع، Turnstile، تبديل الحساب) | 35/35 (`E2E_SUITE=ui`) |

## لماذا لا تنقطع الطلبات؟

- **الموقع الجديد:** لا يكتب الطلب ولا يقرؤه من Firestore. الكتابة عبر Worker v2، والتتبع عبر ملخص الـ Worker برمز التتبع.
- **التبويبات القديمة (505e7b1):** ترسل الطلب إلى Worker v1 أيضًا، وهو يكتب بحساب خدمة لا تخضع للقواعد. كتابتها المباشرة يفشل بصمت، وهذا متوقع في كودها. **شرط ذلك أن يبقى v1 يعمل** حتى تقاعده.
- **الأثر الوحيد:** صفحة النجاح في تبويب قديم لا تعرض تفاصيل الطلب. الطلب نفسه محفوظ.

## خطوات النشر (كل خطوة بموافقة)

1. **قبل النشر:**
   - تأكد أن القواعد المنشورة ما زالت = `firestore.rules.on-delivery`، وخذ نسخة منها (نقطة الرجوع).
   - تأكد أن v1 يعمل.
2. **النشر:** انشر `firebase/firestore.rules.on-delivery-final` بالطريقة نفسها المستخدمة في نشر 2026-11-19 (ruleset جديد ثم تحديث release). لا تنشر من جذر المستودع.
3. **التحقق مباشرة بعد النشر، دون إنشاء طلب:**
   - الصفحة الرئيسية والمتجر يقرآن المنتجات.
   - لوحة التحكم تعرض الطلبات للأدمن.
   - «طلباتي» لزبون مسجّل.
   - تتبع طلب بالرمز.
4. **أول طلب حقيقي بعد النشر:** راقب أن يصل Telegram مرة واحدة، وأن يُحجز المخزون ولا يُخصم.
5. **الرجوع:** أعد نشر النسخة المأخوذة في الخطوة 1. القواعد لا تغيّر أي بيانات.

## غير مشمول هنا (مراجعة لاحقة)

- **`products.update`:** أي مستخدم مسجّل يستطيع تعديل أرقام التقييم. الإغلاق يحتاج نقل حساب التقييم إلى الـ Worker أولًا.
- **`reviews.create`:** أي مستخدم مسجّل يستطيع إنشاء تقييم دون شراء.
