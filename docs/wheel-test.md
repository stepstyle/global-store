# عجلة الجوائز — نسخة تجريبية مغلقة (المرحلة D)

> **الحالة: مغلقة (OFF) افتراضيًا.** لا تعمل في الإنتاج إطلاقًا:
> - الـ Worker في الإنتاج يرفض الإقلاع إذا كان `WHEEL_MODE` غير `off`، وهذا مثبت باختبار.
> - بناء الموقع للإنتاج لا يحتوي أي كود للعجلة حتى لو ضُبط `VITE_WHEEL_MODE=test`، وهذا مثبت باختبار X22.
>
> لا تُشغَّل حملة حقيقية ولا تُمنح جوائز حقيقية قبل اعتماد الشروط المالية والقانونية في الأردن.

## كيف تعمل (للتجربة المحلية فقط)

| البند | القاعدة |
|---|---|
| الهوية | حساب Firebase موثّق (Google أو البريد). لا يُعتمد على IP ولا على رقم هاتف غير موثّق. الضيف لا يدوّر. |
| الفرص | فرصة أولى لكل حساب، وفرصة إضافية عن كل طلب **مُسلَّم** قيمة منتجاته المدفوعة ≥ الحد الأدنى. تُمنح مرة واحدة لكل طلب، وتُسحب إذا أُرجع الطلب بعد التسليم. |
| السحب | يجري على الـ Worker بمولّد عشوائي آمن (CSPRNG)، والمتصفح يعرض النتيجة فقط. كل نتيجة تُخزَّن، سواء جائزة أو «حظ أوفر». |
| التكرار | تحديث الصفحة أو فتح تبويب ثانٍ أو إعادة الإرسال يعيد **النتيجة نفسها** ولا يسحب مرة ثانية. اختبار W04 أرسل 10 طلبات متزامنة فنتج سحب واحد. |
| المخزون | لكل جائزة كمية في `wheelPool`، تُنقص في الـ Commit نفسه، فلا تُمنح أكثر من الكمية حتى مع التزامن (W05). |
| الميزانية | تُرفض الحملة كلها إذا تجاوز مجموع (الكمية × التكلفة) الميزانية. |
| الاستلام | الجائزة تُرفق بطلب الزبون المسجّل كسطر سعره 0: تُحجز مع الطلب، وتُخصم من المخزون عند التسليم فقط، وتُحرَّر عند الإلغاء. |
| الحد الأدنى | يُحسب على المنتجات المدفوعة (المجموع الفرعي ناقص الخصم)، بدون التوصيل وبدون الهدية. |
| إلغاء الطلب | تعود الجائزة «صالحة» (`giftOnCancel: return`) أو تنتهي (`expire`)، حسب إعداد الحملة. |
| الواجهة | صفحة `/wheel` يفتحها الزبون بنفسه، بلا نافذة منبثقة إجبارية. فيها منطقة `aria-live` تعلن النتيجة، ويتوقف التحريك مع `prefers-reduced-motion`، وزر يعمل بلوحة المفاتيح، ونص الشروط. |
| حساب موثّق | التدوير يتطلب بريدًا موثّقًا (`email_verified`، وحسابات Google موثّقة تلقائيًا). **هذا عائق أمام الحسابات الرخيصة فقط، وليس إثباتًا لشخص واحد.** |
| هاتف التوصيل | حد **للهدايا المفتوحة في الوقت نفسه** (`openGiftsPerPhone`، افتراضيًا 1)، أي المحجوزة لطلب لم يُسلَّم بعد. يتحرر الحد عند التسليم أو الإلغاء، فيبقى للزبون الحقيقي حق الجوائز اللاحقة بعد كل طلب مُسلَّم (W17). الهاتف **غير موثّق وقد يكون مشتركًا**: هو وسيلة تقليل فقط وليس إثبات هوية. |
| خصوصية الهاتف | يُحفظ مفتاح HMAC-SHA256 بسرّ موجود على الخادم فقط (`WHEEL_PHONE_SECRET`، 32 حرفًا على الأقل). لا يُحفظ الرقم نفسه، ولا يكفي Hash عادي لأن أرقام الأردن قابلة للتخمين، ولا يدخل السر في أي بناء للمتصفح. الوضع التجريبي يرفض العمل بدونه. |
| صلاحية الجائزة | للجائزة غير المستلمة مدة صلاحية `prizeValidDays` (افتراضيًا 30). بعدها تُرفض (`WHEEL_PRIZE_EXPIRED`)، ويعيدها الـ Cron إلى المخزون **مرة واحدة فقط**، وفقط إن لم تكن محجوزة لطلب قائم (W21، W23–W26). |
| الفرصة الأولى | `freeFirstChance` مفعّلة افتراضيًا (فرصة ترحيب). إيقافها خيار موجود (W18) **لا يُعتمد بدون موافقة المالك**. |
| المتصفح | قواعد Firestore لا تسمح بقراءة أو كتابة أي مجموعة للعجلة، لا في القواعد الحالية ولا في النهائية (5 حالات في اختبار القواعد). |

## الإعدادات (كلها قيم تجريبية وليست قرارات)

مستند الحملة: `wheelCampaigns/{WHEEL_CAMPAIGN}`. يكتبه المالك عبر حساب الخدمة فقط.

```json
{
  "active": true,
  "startsAt": "2026-01-01T00:00:00Z",
  "endsAt": "2026-02-01T00:00:00Z",
  "minOrderJod": 5,
  "budgetJod": 10,
  "noPrizeWeight": 60,
  "giftOnCancel": "return",
  "terms": "…",
  "prizes": [
    { "id": "test-a", "label": "جائزة تجريبية", "productId": "<منتج حقيقي في المتجر>", "weight": 30, "quantity": 3, "unitCostJod": 1 }
  ]
}
```

ويُضاف لكل جائزة مستند `wheelPool/{campaign}_{prizeId}` فيه `{ "remaining": <الكمية> }`.

- **الاحتمال** = وزن الجائزة ÷ مجموع الأوزان المتاحة، ويدخل فيها `noPrizeWeight`. الجائزة التي نفدت لا تدخل السحب.
- **الحد الأدنى 5 د.أ مقترح وغير معتمد.** لا أسماء ولا أسعار ولا احتمالات حقيقية في الكود.

## التشغيل المحلي

- **الـ Worker:** `WHEEL_MODE=test` و`WHEEL_CAMPAIGN=<id>` و`STOCK_POLICY=on_delivery`، على Emulator فقط.
- **الموقع:** `VITE_WHEEL_MODE=test` في بناء محلي (local-test أو sandbox)، ثم افتح `#/wheel`.
- **الاختبارات:**
  - `workers/order-worker/test/unit/wheel.test.mjs`
  - `workers/order-worker/test/wheel.test.mjs` (W01–W16)
  - `tests/unit/orderSubmit.test.mjs` (لا يُرسل رقم الجائزة إلا مع طلب مسجّل)
  - `tests/deploy-guard/build-browser.test.mjs` (X22)

## ما لا تمنعه هذه الحماية (مخاطر باقية)

- **شخص واحد بعدة حسابات Google وعدة أرقام هواتف:** يحصل على فرصة ترحيب لكل حساب. لكن كل هدية تحتاج طلبًا مدفوعًا لا يقل عن الحد الأدنى ويُسلَّم فعلًا، والهدايا المفتوحة محدودة لكل رقم. الخسارة القصوى = تكلفة الجوائز ضمن الميزانية المحددة سلفًا.
- **استنزاف مخزون الجوائز بحسابات وهمية لا تشتري:** كل جائزة غير مستلمة تعود إلى المخزون بعد انتهاء صلاحيتها.
- **تقليص المخاطر أكثر (يحتاج قرار المالك):** تقصير `prizeValidDays`، أو جعل فرصة الترحيب «بلا جائزة عينية» (خصم صغير مثلًا)، أو مراجعة يدوية للطلبات التي تحمل هدية قبل الشحن.

## قرارات مطلوبة من المالك قبل أي حملة حقيقية

1. الإطار القانوني في الأردن (السحوبات والجوائز الترويجية): هل يلزم ترخيص أو إشعار لوزارة الصناعة والتجارة؟
2. قائمة الجوائز الحقيقية وتكلفتها وكمياتها، والميزانية الكلية.
3. الحد الأدنى للطلب (المقترح 5 د.أ).
4. مصير الجائزة عند إلغاء الطلب: `return` أو `expire`.
5. مدة الحملة ونص الشروط المعروض للزبون.
6. هل تُعرض العجلة للضيوف بدعوة لتسجيل الدخول فقط، كما هو الآن؟

## ما لم يُنفَّذ بعد (عمدًا)

- لوحة تحكم إدارية لإنشاء الحملة. الإعداد حاليًا يدوي عبر حساب الخدمة.
- استعلام الـ Cron يقرأ `wheelSpins` بحسب `status`، وهو فهرس حقل واحد ينشئه Firestore تلقائيًا. التحقق من التاريخ يجري في الكود (50 مستندًا في كل تشغيل).
- ظهور سطر الهدية مميَّزًا في لوحة الإدارة. هو موجود في `items` (`gift: true`، السعر 0) وفي `wheelGift`، والإشعارات تعرضه كسطر عادي.
- تقارير الحملة: عدد الدورات والجوائز والتكلفة الفعلية.
