## 3. سباق المتصفح والـ Worker (حتى نهاية المرحلة 2)

المبدأ: **`orderLedger/{orderId}` هو قفل منع التكرار** — يكتبه الـ Worker فقط، ويُنشأ بشرط `exists:false`
في نفس الـ commit الذري مع خصم المخزون. المتصفح لا يكتبه أبدًا، فلا يستطيع مسحه.

| الترتيب | سلوك Worker v2 | المتوقع |
|---|---|---|
| المتصفح أولًا ← Worker | `orders/{id}` موجود وعمره < 15 دقيقة ← لا يلمسه؛ ينشئ ledger + خصم | ledger واحد، خصم واحد، إشعار واحد |
| Worker أولًا ← المتصفح | ينشئ order + ledger + خصم ذريًا؛ `setDoc` المتصفح يستبدل order فقط | ledger سليم، خصم واحد، إشعار واحد |
| كتابة المتصفح تفشل | Worker ينشئ كل شيء | طلب واحد |
| Worker يفشل | لا ledger/خصم/إشعار | حالة اليوم — تُرصد بمقارنة `orders` مع `orderLedger` |
| order موجود وعمره > 15 دقيقة، بلا ledger | رفض `409` | لا مساس بالطلبات القديمة |

- الإشعارات تُبنى من **ledger** (أسعار الخادم)، لا من مستند الطلب.
- **حد مقبول مؤقتًا:** مستند الطلب قد يحمل أسعار المتصفح حتى المرحلة 2.
- **محسوم من قواعد الإنتاج (2026-11-03):** `orders` update للأدمن فقط ← في الترتيب الثاني تُرفض
  كتابة المتصفح (وتُبتلع بصمت). وفي الترتيب الأول يستبدل الـ Worker (حساب خدمة) مستند المتصفح.
  ⇒ عندما ينجح الـ Worker، **المستند النهائي دائمًا نسخته**. التفاصيل: [`firebase/rules-test/README.md`](../../firebase/rules-test/README.md).

## 4. أشكال المنتجات (من الكود — لم تُفحص البيانات الفعلية بعد)

| الشكل | مصدر المخزون الحقيقي | ملاحظة |
|---|---|---|
| أ. بلا حقل `variants` | `stock` العام | منتجات قديمة |
| ب. `variants: []` | `stock` العام | |
| ج. `variants` غير فارغة | `variants[i].stock` | `stock` العام رقم يدوي مستقل (افتراضي 0) — **ليس مجموعًا** |
| د. متغير بالاسم `'.'` | `variants[i].stock` | الواجهة تخفي الاسم |
| هـ. متغير لون بلا اسم | `variants[i].stock` | مسموح في التحقق للألوان |
| و. مستورد من CSV | `stock` العام | بلا متغيرات، `price` قد يكون 0 |

مشكلة مؤكدة: `ProductCard.tsx:99-100` يحدد التوفر من `product.stock` العام فقط ← منتج بألوان متوفرة
و`stock` عام = 0 يظهر «غير متوفر»؛ وv1 يخصم من هذا الرقم.

**مفتوح:** وجود متغيرات بلا `id`/بمعرّف مكرر، أرقام محفوظة كنص، وأعداد كل شكل
← يحتاج فحصًا (موافقة منفصلة) أو عيّنات يصدّرها صاحب المتجر من Console.

Worker v2 يجب أن: يطابق المتغير بـ `variant.id` فقط (لا بالاسم)، ويرفض (`409`) متغيرًا مفقودًا أو بلا `id`،
ويخصم من `variants[i].stock` للشكل ج–هـ ومن `stock` العام لـ أ/ب/و.
**قرار مطلوب:** هل يُحدَّث `stock` العام لمنتجات المتغيرات (مثلًا = مجموع المتغيرات) أم يُترك؟

## 5. بيئة الاختبار المعزولة

### المستوى 1 — محلي بالكامل (بلا موارد سحابية ولا أسرار)

| المكوّن | الأداة |
|---|---|
| Firestore | Firebase Emulator على `127.0.0.1:8080`، مشروع `demo-dairsharaf` (بادئة `demo-` تمنع أي اتصال بمشروع حقيقي) |
| Worker | `npx wrangler dev` (وضع محلي) |
| Telegram / SendGrid | خادم Node وهمي محلي يسجّل ويعدّ الطلبات |
| Turnstile | مفاتيح الاختبار الرسمية من Cloudflare |
| الواجهة | `npm run dev` بمتغيرات تشير للمحاكي والـ Worker المحلي |

متطلب: v1 يكتب عناوين `firestore.googleapis.com`/Telegram/SendGrid مباشرة في الكود ← v2 يقرأها من `env`
(`FIRESTORE_BASE_URL`, `TELEGRAM_API_BASE`, `SENDGRID_API_BASE`) ليعمل مع المحاكي والخوادم الوهمية.

**حواجز إلزامية:**
- Worker يرفض العمل إذا `FIREBASE_PROJECT_ID == antastore1-82b50` و`ENVIRONMENT != production`.
- الواجهة ترفض وضع الاختبار إذا كان مشروع Firebase هو مشروع الإنتاج.
- سكربتات الاختبار ترفض العمل دون `FIRESTORE_EMULATOR_HOST`.
- `src/services/firebase.ts` يحتوي إعدادات الإنتاج مكتوبة مباشرة ← **أي `npm run dev` حالي يكتب في قاعدة الإنتاج.**
  لا تُجرَّب صفحة الدفع محليًا قبل نقل الإعدادات إلى `VITE_FIREBASE_*`.

### المستوى 2 — Staging سحابي (قبل النشر فقط، يحتاج موافقة)

مشروع Firebase منفصل، Worker `anta-order-notify-staging`، بوت تيليجرام للاختبار، SendGrid `sandbox_mode`،
حساب خدمة من مشروع الاختبار فقط، أسرار عبر `wrangler secret` فقط.

## 8. الرجوع (Rollback)

| المكوّن | الطريقة |
|---|---|
| Worker | Cloudflare → Deployments → Rollback (أو `wrangler rollback`) |
| الواجهة | Vercel → Deployments → Instant Rollback |
| قواعد Firestore | Firebase Console → Rules → سجل النسخ |
| الكود | `git revert` على هذا الفرع |

ترتيب الرجوع عند وجود الواجهة v2: **الواجهة أولًا ثم الـ Worker** (`/v2/orders` على Worker قديم = 404 ← فشل آمن).
